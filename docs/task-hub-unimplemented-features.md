# 任务大厅未实装功能清单

生成日期：2026-06-04

## 背景

本清单基于当前 `schemav-frontend/src/views/TaskHubView.tsx` 的任务大厅首页 UI 梳理。当前首页已经完成一版工作台式 UI 基线，但其中部分入口只是视觉占位，或只做了前端派生展示，还没有对应的数据模型、后端接口或完整交互。

后续实装时建议优先保持现有 `/api/tasks` CRUD 能力稳定，再逐步补齐下面的功能。

## P0：已展示但当前不可用的入口

| 功能 | 当前表现 | 缺失内容 | 建议下一步 |
| --- | --- | --- | --- |
| 我的收藏 | 左侧有“我的收藏”，按钮处于 disabled，数量固定为 0。 | 任务收藏字段、收藏/取消收藏接口、收藏筛选逻辑。 | 先在任务模型中增加 `favorite` 或 `starred` 字段，再接入卡片星标按钮和左侧收藏筛选。 |
| 导入大屏模板 | 右侧“快捷操作”中展示“导入大屏模板”，按钮 disabled。 | 模板来源、导入流程、模板解析与任务创建逻辑。 | 先定义模板数据结构和导入后的任务生成规则，再做弹窗或文件上传入口。 |
| 管理数据源 | 右侧“快捷操作”中展示“管理数据源”，按钮 disabled。 | 数据源列表、连接配置、数据源 CRUD、编辑器绑定关系。 | 建议等编辑器数据绑定能力明确后再实装，避免先做空壳数据源。 |
| 回收站 | 右侧“快捷操作”中展示“回收站”，按钮 disabled。 | 软删除字段、恢复/永久删除接口、回收站列表页或弹窗。 | 将当前删除任务改为软删除，再增加恢复和永久删除能力。 |

## P1：入口可见，但只有 UI 或派生逻辑

| 功能 | 当前表现 | 缺失内容 | 建议下一步 |
| --- | --- | --- | --- |
| 卡片收藏星标 | 每张任务卡片封面右上角有星标按钮，但没有点击逻辑。 | 收藏状态、点击处理、持久化接口、已收藏样式。 | 和“我的收藏”一起实装，避免重复改动。 |
| 项目分组 | 左侧有销售分析、运营看板、财务报表、人事分析、供应链、未分组。当前分组由任务名称/描述关键字前端推断。 | 真实分组字段、分组管理、分组筛选持久化。 | 第一版可给任务增加 `groupId`，分组列表先用固定枚举，后续再做自定义分组。 |
| 新增分组按钮 | “项目分组”标题右侧有加号按钮，但未绑定操作。 | 新建分组弹窗、分组字段、分组保存接口。 | 等真实分组字段落地后再启用。 |
| 项目状态 | 左侧展示全部状态、已保存、未保存、协作中；当前所有任务都被派生为“已保存”，其他状态数量固定为 0。 | 任务状态字段、状态变更规则、未保存/协作中来源。 | 先定义任务状态枚举，例如 `saved`、`draft`、`collaborating`，再接筛选和卡片状态标签。 |
| 最近更新 | 右侧列表取任务按 `updatedAt` 排序后的前 5 条。 | 真实活动流、操作人、操作类型、活动时间。 | 短期可继续用任务更新时间；中期增加 activity log。 |
| 顶部视图切换 | 顶部有网格/列表两个图标按钮，但没有状态和切换逻辑。 | 列表视图、当前视图状态、用户偏好保存。 | 先实现本地 grid/list 切换，再考虑持久化用户偏好。 |
| 通知按钮 | 顶部有通知图标按钮，但无点击逻辑。 | 通知列表、未读数、通知来源。 | 若短期没有协作能力，可先隐藏或改成 disabled，避免误导用户。 |
| 帮助按钮 | 顶部有帮助图标按钮，但无点击逻辑。 | 帮助文档、快捷引导、外链或弹窗。 | 可先接本地文档或简单帮助弹窗，成本较低。 |
| 用户头像 | 顶部显示固定 `L` 头像，无菜单和真实用户信息。 | 用户信息、账号菜单、登录/退出能力。 | 如果 MVP 暂无认证，可先保留静态头像；实装认证时再接入。 |

## P2：已经可用，但体验还可继续补齐

| 功能 | 当前表现 | 可改进点 | 建议下一步 |
| --- | --- | --- | --- |
| 搜索 | 可按任务名称和描述前端过滤。 | 没有服务端搜索、没有高亮命中、筛选条件不会保留。 | 任务量小可继续前端搜索；任务量变大后再做服务端查询。 |
| 更新时间筛选 | 可按今天、近 7 天、近 30 天前端过滤。 | 使用本地时间判断；无自定义时间范围。 | 第一版可保持；后续增加日期范围选择。 |
| 新建任务 | 弹窗可创建任务。 | 缺少模板选择、分组选择、创建后可配置跳转策略。 | 后续可以在新建弹窗中加入分组和模板入口。 |
| 复制/删除 | 更多菜单中已有复制和删除，并接入现有接口。 | 删除是硬删除；复制后缺少跳转或明确定位。 | 配合回收站改软删除；复制成功后可高亮新任务。 |
| 预览 | 预览入口会打开编辑器预览地址。 | 缺少独立预览页体验、加载失败提示。 | 保持当前入口，后续再独立优化预览页。 |

## 推荐实装顺序

1. 收藏体系：任务字段 + 星标点击 + 我的收藏筛选。
2. 真实分组：任务 `groupId` + 分组筛选 + 新建任务选择分组。
3. 列表/网格视图切换：先纯前端实现，提升首页可用性。
4. 回收站：把删除从硬删除改为软删除，补恢复/永久删除。
5. 模板导入：定义模板格式，再实现导入大屏模板入口。
6. 数据源管理：等编辑器数据绑定需求明确后再做。
7. 通知、帮助、用户菜单：根据是否引入账号/协作体系决定实装深度。

## 当前应避免的做法

- 不要一次性把所有占位入口都接成弹窗空壳，否则会增加后续返工。
- 不要先做复杂账号/通知体系，除非项目明确进入多人协作路线。
- 不要为了分组和状态临时使用更多前端关键字推断；下一步应补真实字段。
- 不要在没有软删除设计前继续扩展删除相关 UI。
